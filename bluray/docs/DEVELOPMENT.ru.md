## Устройство репозитория

| Путь | Назначение |
| --- | --- |
| `src/mpc-hc`, `include`, `src/thirdparty` | Исходники MPC-HC и закреплённые зависимости, включая LAV |
| `bluray/sources.json`, `bluray/imports.json` | Точные версии компонентов и происхождение переносов |
| `bluray/patches`, `bluray/ports` | Сопровождаемые патчи библиотек/LAV и адаптации исходников |
| `bluray/tools` | Сборка, регрессии, проверка публикации и упаковка |
| `bluray/docs`, `bluray/CHANGELOG*.md` | Парные руководства, проверки, журнал переносов и история форка |
| `bluray/vendor`, `bluray/dependencies`, `bluray/build`, `bluray/out`, `bluray/diagnostics`, `bluray/runtime` | Игнорируемые локальные исходники, результаты и тестовые данные |

Клонируйте форк с его Git-историей; команды ниже выполняются из его корня.
Сохраняйте `origin` для форка и `upstream` для официального MPC-HC. Перед сборкой
проверяйте ревизии; не заменяйте историю скачанным снимком файлов. Схема версии —
[исходная версия MPC-HC и номер выпуска форка](RELEASING.ru.md).

## Исходники и инструменты

Основа — тег `2.8.2` из `clsid2/mpc-hc`, коммит
`a84d0cf38a1866f3518bb819c901300dacff5a9b`. Сохраняйте историю и ревизии
подмодулей. Выбранный донор — `270cfdd4369224dd4108d0b1d1b8a4ab7b8fc56d`
из `ttonych/mpc-be_bluray`. См. [sources.json](../sources.json).

Нужны Visual Studio 2022 с C++, x64 MFC/ATL и Windows SDK 10.0.19041.0,
NASM 2.16.03, Git, PowerShell и Python 3.12 или новее. Скрипты находят Visual
Studio и меняют окружение только текущего процесса. Скрипт сборки плеера
явно задаёт пути SDK/UCRT, найденные VsDevCmd.

В корне репозитория загрузите закреплённые зависимости:

```powershell
git submodule update --init --recursive
```

Прерванное клонирование не означает готовую рабочую копию. У LAV есть свои
подмодули FFmpeg, libbluray и qsdecoder. При восстановлении загрузки
сохраняйте зафиксированные ревизии.

## Сборка runtime и плеера

```powershell
./bluray/tools/test-bootstrap.ps1
```

Скрипт проверяет/загружает архив libbluray, применяет native-патчи по порядку
(`mouse-page-v1`, `playmark-seek-v1`) и независимый Java-патч `bdj-toggle-v1`.
Проверяет чистое и повторное применение, отказ затирать неожиданные правки,
затем компилирует извлечённые рабочие функции обработки меток и запроса
состояния процесса с искусственными тестовыми окружениями компилятором x64.
DLL/JAR libbluray и диски не проверяются этим скриптом. Байты патчей и манифесты
сохраняют хеши донора; `imports.json` отмечает адаптированные запускатели тестов.

До плеера соберите runtime меню: он предоставляет закреплённые заголовки.
`$javaRoot` должен указывать на Temurin JDK 21.0.12.1+1 x64 с javac 21.0.12.1.
Подготовка зависимостей должна успешно завершиться; альтернативно передайте
уже проверенный каталог зависимостей x64 с зафиксированной основой vcpkg.

```powershell
./bluray/tools/prepare-dependencies.ps1
./bluray/tools/build-libbluray.ps1 -DependencyRoot ./bluray/build/vcpkg_installed/x64-windows
./bluray/tools/build-bdj.ps1 -JavaHome $javaRoot
./bluray/tools/test-bdj-toggle.ps1 -JavaHome $javaRoot
./bluray/tools/test-menu-components.ps1
```

Для плеера Release x64 добавьте `nasm.exe` в PATH и выполните:

```powershell
./bluray/tools/build-player-core.ps1
```

Либо передайте `-NasmDirectory` с локальным каталогом NASM. Скрипт использует
цель решения `Apps\mpc-hc`, сохраняя порядок сборки библиотек. Журналы находятся
в игнорируемом `bluray/diagnostics`, результат — в штатном `bin`. Собирается
плеер со встроенными английскими ресурсами. LAV, языковые DLL, новый runtime
меню и релизный пакет собираются отдельно. Штатные инструкции полной сборки
сохранены в [Compilation.md](../../docs/Compilation.md).

Для русской ресурсной DLL используйте отдельное окружение Python:

```powershell
python -m venv bluray/tools/.venv
./bluray/tools/.venv/Scripts/python.exe -m pip install -r bluray/tools/requirements-resources.txt
./bluray/tools/build-russian-resources.ps1
```

Используется штатная генерация ресурсов без нормализации отслеживаемых PO-файлов.

## Локальный прототип LAV и portable-копия

MSVC-конфигурация использует современную оболочку MSYS и GNU make 4.4.1
(проверенная ревизия пакета/хеш указаны в `sources.json`). Задайте `$msysRoot`,
`$makeBin` и `$nasmBin` как свои каталоги инструментов; make должен работать
с выбранным runtime MSYS. Библиотеки плеера, включая zlib, уже должны быть собраны.

```powershell
python ./bluray/tools/apply-lav-patch.py
./bluray/tools/build-lav-msvc.ps1 -MsysRoot $msysRoot -MakeDirectory $makeBin -NasmDirectory $nasmBin -Configure
python ./bluray/tools/test-lav-menu-bridge.py
python ./bluray/tools/test-lav-navigation-timestamps.py
python ./bluray/tools/test-lav-mpeg2-stills.py
./bluray/tools/test-lav-runtime.ps1
./bluray/tools/prepare-local-player.ps1 -Destination ./bluray/runtime/test-01
```

Установщик патча проверяет точный коммит LAV, хеш патча и исходных файлов;
посторонние изменения отвергаются. Runtime-тест использует software-декодирование
и Null Renderer, не меняя настройки зарегистрированных фильтров. MSVC-конфигурация
FFmpeg использует Schannel и встроенный AV1; внешние зависимости GCC отсутствуют.
До выпуска нужно проверить обычные файлы и равенство набора кодеков. Журналы
сборки/манифесты лежат в игнорируемом `bluray/diagnostics`.

`prepare-local-player.ps1` требует новый каталог, копирует явный список runtime
и создаёт пустой portable INI. Включены оба Java JAR, русская ресурсная DLL,
манифесты исходников/лицензий. Java и madVR остаются внешними. В тестовом плеере
выберите madVR в настройках вывода и откройте **Настройки > Воспроизведение >
Blu-ray**. Задайте там каталог закреплённой Java или оставьте автоматический поиск.
Не используйте INI установленного плеера или его данные BD-J.

На странице Blu-ray выбирается **Основной фильм** (по умолчанию) или **Меню диска**
для обычного открытия, включая **Открыть DVD/BD** и файл `index.bdmv` диска.
Общий путь открытия распознаёт корень диска, `BDMV`, `index.bdmv` и
`MovieObject.bdmv`; отдельные плейлисты/клипы сохраняют обычное воспроизведение.
Используйте **Открыть DVD/BD** для корня диска или папки `BDMV`. Локальный или
сетевой `.iso` можно открыть или перетащить прямо в плеер: Windows подключает его
только для чтения, а Blu-ray следует тому же выбору меню/основного фильма.
Подключение сохраняется при смене плейлистов и освобождается после закрытия графа;
уже подключённый извне образ используется без принудительного отключения.
Неподдерживаемая структура и ошибки подключения сообщаются пользователю, образ
не передаётся обычному видеопарсеру. Нужна штатная поддержка ISO в Windows;
сторонние программы подключения и другие форматы образов не перенесены.
Временный отдельный пункт открытия меню удалён. Для меню нужен madVR.
Ошибка открытия меню сообщается без скрытого перехода к основному фильму.

Также доступны регион, страна, языки меню/звука/субтитров, Java и отдельные папки
сохранений/кеша BD-J. Названия стран и языков берутся из Windows; можно ввести
ISO-код страны (две буквы) или языка (три буквы). Пустые пути хранилища используют
`bdj-data` рядом с плеером. Настройки действуют при следующем открытии диска;
смена папок не переносит и не удаляет данные. Применение проверяет все поля до
записи; отмена отбрасывает неприменённые правки. Статус Java проверяет Windows-образ JVM
и разрядность. Повреждённую или неподходящую явно выбранную установку применить
нельзя. «Проверить Java» запускает отдельный скрытый java.exe -version: лимит
10 секунд и 64 КиБ вывода, завершение дочерней группы при закрытии настроек или
изменении полей. Переменные окружения с дополнительными опциями Java исключены
только из этого процесса. Успех доказывает запуск Java, не совместимость BD-J
или диска. Автоматический поиск остаётся при открытии диска; для явной проверки
нужно выбрать папку.

Стрелки/Enter управляют меню, Home или штатная команда Title Menu (по умолчанию
Alt+T) вызывает верхнее меню; Apps или Root Menu (Alt+R) — всплывающее.
Главное и контекстное меню используют те же команды навигации. Ограничения диска
сохраняются. Полная матрица языков/дисков/рендера ещё в работе.

**Blu-ray > Совместимость...** открывает 14 закреплённых параметров libbluray:
возраст, профиль плеера, ограничения навигации и сообщаемые возможности. Готовые
варианты, пояснения и необязательные технические сведения сохраняют смысл донора.
Эти возможности сообщаются меню диска; они не добавляют декодеры и не меняют HDR
рендера. Дочернее окно редактирует копию: его ОК подготавливает изменения,
«Применить»/«ОК» основных настроек записывает их. Отмена в любом окне отбрасывает
его неприменённые правки. «По умолчанию»/«Сбросить все параметры» возвращают
автоматические значения в черновике и не сбрасывают сохранения дисков.


**Blu-ray > Данные дисков...** показывает определённые диски и прежние общие
папки: поиск, свои названия, дату открытия, обновление и доступ к папкам.
Используются применённые пути, даже если страница настроек содержит правки.
Переименование и подтверждённый сброс выполняются сразу; отмена настроек их не
отменяет. Сброс выбирает пустые папки сохранений/кеша при следующем открытии
диска. Прежние файлы и активные сеансы сохраняют свои пути; данные не удаляются.
Общая старая папка может содержать несколько дисков и не сбрасывается как один
определённый диск. Кнопка кеша использует текущую применённую папку, которая
может быть общей. Собственное название не переименовывает физическую папку.

./bluray/tools/test-disc-java.ps1 проверяет хранилище и процессы Java на
искусственных данных. test-bluray-opening-settings.py проверяет применение с
образами JVM. Установленные профили и реальные сохранения тесты не используют.

## Переносы и публикация

Сохраняйте общие алгоритмы и патчи близкими к донору; отдельно адаптируйте UI,
граф DirectShow, дорожки и часы воспроизведения. Сопровождаемый патч LAV даёт
выбор дорожек по PID, границы PlayItem и начало presentation. Каждый перенос, отложенную правку
и собственную проверку HC фиксируйте в [PORTING.ru.md](PORTING.ru.md).

Используйте локальные feature/fix/update-ветки. После разрешённого создания
remote изменения проходят PR и обязательные быстрые проверки в main. Полный
CI запускается вручную для проверенных кандидатов. Для публикации нужны
проверки данных/истории и точного ZIP по [AGENTS.ru.md](../../AGENTS.ru.md).
Скрипты ничего не публикуют и не меняют установленные плееры. Проверки runtime
требуют отдельного portable-профиля, копий/искусственного хранилища BD-J,
закреплённой Java и madVR 210.

Регрессия команд (MSVC x64, включая отрицательный контроль на исходном коде):

```powershell
. ./bluray/tools/Enter-BuildEnvironment.ps1
python ./bluray/tools/test-navigation-commands.py
python ./bluray/tools/test-navigation-commands.py --baseline
python ./bluray/tools/test-navigation-display.py
python ./bluray/tools/test-bluray-opening-settings.py
python ./bluray/tools/test-bluray-compatibility.py
```

При адаптации мыши меню сохраняйте обновление видимости полноэкранных панелей,
даже когда диск обработал движение. Проверяйте нижний край в меню/фильме/возврате;
штатную панель и OSD рендерера проверяйте отдельно. Основной режим madVR —
D3D11 fullscreen windowed; exclusive не является условием начала проверки.

Регрессия ISO: `./bluray/tools/test-iso-opening.ps1`; необязательный
`-ImagePath` проверяет владение настоящим подключением. В окружении MSVC
запустите `python ./bluray/tools/test-iso-routing.py` для маршрутизации и ошибок.

## Проверки и упаковка кандидата

`prepare-build-tools.ps1` из `bluray/tools` загружает NASM и make с закреплёнными
хешами; оболочка MSYS берётся из Git for Windows. `test-components.ps1 -JavaHome
$javaRoot` запускает полный набор нативных проверок и тест настоящего JAR. Повторная
подготовка сборочного окружения безопасна и не увеличивает PATH.

Быстрые PR-проверки охватывают новые blobs всей отправляемой истории, проверенные
метаданные новых авторов/коммитеров, документы, RU-ресурсы и регрессии упаковки.
Авторство upstream сохраняется. Полный `bluray-build.yml` запускается только вручную.
`package-player.py` принимает ручное облачное окружение, проверяет чистые исходники
и патч LAV, собирает явный список программ/лицензий/источников с новым portable-INI,
проверяет записанные хеши и создаёт новый ZIP без замены прежних пакетов. После
скачивания: `python bluray/tools/package-player.py --verify <candidate.zip>`.
Java/madVR не включаются, Release не публикуется. Перед выпуском проверьте именно
этот архив по [матрице воспроизведения](VALIDATION.ru.md).

Полный порядок версий, тегов, changelog и перехода от черновика к публикации —
в [руководстве выпуска](RELEASING.ru.md). Документы текущего пакета — Markdown;
генератор offline-HTML из MPC-BE не перенесён. Относительные ссылки на файлы вне
пакета упаковщик переписывает на точный commit исходников.

## Обновление двух источников и зависимостей

Выбирайте обновление отдельно, в ветке `update/`. Сохраняйте исходную историю,
авторов и лицензии; завершайте локальные проверки до PR. Сам выход новой версии
upstream не является поручением сменить основу.

- **MPC-HC:** примите выбранный официальный тег, разрешите конфликты интеграции
  HC/Blu-ray и обновите подмодули до закреплённых тегом ревизий. Проверьте граф,
  настройки, ресурсы, расчёт ревизии и обычное воспроизведение. Обновляйте манифест
  исходников и парные changelog одновременно.
- **MPC-BE Blu-ray:** сравните фиксированный коммит донора с последним учтённым.
  Для каждой правки отметьте: общий перенос, адаптация, уже есть, неприменимо или
  отложено; учитывайте зависимые патчи/тесты. Не сливайте ветку донора целиком.
  Сохраняйте общие алгоритмы близкими и записывайте результаты HC в журнал переносов.
- **LAV:** сохраняйте выбор PID, границы PlayItem, timestamps и поведение
  статичных MPEG-2 кадров адаптера. Переносите патч на выбранную ревизию
  с проверенными новыми манифестами; проверяйте меню и обычные файлы.
  Внутренняя libbluray LAV остаётся отдельной зависимостью.
- **libbluray:** перед удалением/адаптацией патча проверьте исправления upstream.
  Проверяйте версии DLL/JAR/заголовков вместе, в том числе внутренние структуры
  плейлистов для звука меню: это не стабильный публичный ABI. Сейчас движок меню
  принимает 1.5.0. Осознанно обновляйте проверки версии и записи пакета/исходников/
  лицензий; совпадение хеша не является проверкой совместимости API/ABI.
- **Java:** при необходимости отдельно закрепляйте JDK сборки и проверенный
  runtime воспроизведения. После изменений Java пересоберите оба JAR, выполните
  HAVi-тесты на настоящем JAR, затем проверьте запуск BD-J, навигацию и сохранения.

При каждом обновлении сохраняйте прежний кандидат, используйте новую изолированную
portable-папку и проверяйте полученный облачный ZIP до выпуска. Не заменяйте
манифесты только ради подавления необъяснённого расхождения хеша или исходников.

## Кодировка текста

Markdown форка хранится в UTF-8. В PowerShell явно указывайте `-Encoding UTF8`
при чтении и записи: преобразование через системную кодировку может повредить
русские подписи даже в английском README. Сохраняйте кодировки/BOM и окончания
строк ресурсов, особенно `.rc`, без массового преобразования. Быстрый сканер
требует корректный UTF-8 и точные подписи EN/RU-навигации; помимо автоматической
проверки просматривайте отображаемый текст.

## Сопровождение версии форка и updater

Для следующего выпуска измените `MPCHC_BLURAY_RELEASE` в `include/BlurayVersion.h`.
Основа остаётся в `include/version.h` и должна совпадать с `sources.json`.
`fork_version.py` передаёт номер упаковщику/манифестам; сборки плеера/ресурсов и
упаковщик вызывают `check-player-version.ps1`, отклоняющий устаревшие файлы.
Сохраняйте совместимость числовых версий ресурсов Windows с исходным плеером.

После правок версии, updater или расчёта ревизии выполните в окружении MSVC:

```powershell
python ./bluray/tools/test-fork-release.py
./bluray/tools/check-player-version.ps1 -IncludeRussian
```

Тест компилирует рабочие C++ парсеры тегов/ответа API, проверяет единый источник
версии и запускает настоящий batch расчёта ревизии во временном Git-репозитории.
Быстрый Linux CI использует g++ для парсера/версии; Windows batch там пропускается
и должен пройти локально. Общий компонентный скрипт включает эту проверку.

Updater получает не более 100 опубликованных выпусков одним ответом GitHub,
учитывает prerelease и выбирает максимальный строгий числовой тег форка.
Черновики, чужие URL выпусков, повреждённые/слишком большие ответы и ошибки API
обрабатываются явно. Размер ограничен 4 MiB; у транспорта есть тайм-ауты и срок
чтения. Пропущенная версия и время последней проверки используют отдельные ключи
форка. Проверяйте нативные EN/RU-окна отдельно от парсеров; пустой живой список
не проверяет скачивание будущего выпуска. Установщика в этом пути нет.
